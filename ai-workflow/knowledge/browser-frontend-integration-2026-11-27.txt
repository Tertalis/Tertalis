REPRODUCED FINDINGS AND CORRECTIONS
----------------------------------
1. Snapshot recovery race: an Emit at p=1 arrived while a snapshot captured
   at p=0 was in flight. Recovery coalescing discarded the only new update;
   client stayed at p=0 indefinitely. Session now remembers the extra gap,
   schedules another snapshot, and retries failed snapshots. Close cancels
   scheduled recovery; obsolete run responses cannot replace current state.
2. Restart uncertainty: a restarted host rotates credentials. Old tabs get
   HTTP 401 before receiving a new run event; accepted actions stayed pending
   forever. Terminal stream failures now settle pending actions as unknown.
   Credential rotation intentionally requires a fresh launch link.
3. Pending bound: with maxInbox=2/idempotency=4, repeatedly submit/drain left
   20 pending records. Pending actions now count toward the retention limit;
   admission returns busy when full. Settled records can be evicted without
   forgetting an older pending id. Limits must be positive integers.
4. Snapshot size: nine individually valid 256 KiB log values produced a
   2359369-byte snapshot; kit permits only 2097152 bytes. Host logs now retain
   at most 1 MiB of encoded tail items, as well as their item-count limit.
   A real HTTP regression proves the snapshot fits and preserves position.
Cached Results are also frozen at resolve time so later owner mutation cannot
make duplicate replies disagree with the authoritative invocation log.
