DELIVERED BEHAVIOUR
-------------------
A  Existence, interaction, inspection: authoritative personality, empty personal
   memory, fresh situation-first prompts (no replayed chat), provisional tag
   output contract (only closed <say> is speech), prepare/execute/process Jobs,
   breakpoint mode pausing before inference and after the response with
   prompt/response replacement recorded as interventions, raw output and
   timing records, continuous operation, save/restore incl. re-offered
   prepared/generated inferences.
B  Memory: almost-literal experiences, deliberate memories with provenance,
   recent window plus lexical automatic selection with explicit absence,
   <recall> continuation with found/no-further/no-match outcomes, bounded
   continuation, "how do you know" provenance, developer memory injection.
C  Things to do: activities, dependencies, notBefore, expiry, suspend/resume/
   abandon/amend, recorded eligibility and tiered selection, State/Important
   State/Queue/Important/Interrupt/Choice directives, input amending open
   input work, finish/cancel interruption policies with kept partial output,
   active-time pressure excluding debugger pauses, rechecks, deterministic
   periodic checks.
D  Independent activity and execution state: deterministic Minesweeper with
   state independent of inference, optional activity yielding to input,
   related input acting on the game, active/resting/explicitly inactive
   lifecycle, driver-imitated quiescence, restart and activation notices,
   periodic escalation of a waiting game.
E  Rules: ordered scoped rules shown by number, AI rule establishment/
   revision/reorder/retire on editable rules only, disregard per step,
   protected initial and developer rules (rejections recorded), loss
   investigation with the revealed final board.
F  Passive processing: memory reflection with cursor and scheduled reactions,
   salient candidates with limit and expiry, may run while inactive or
   resting, never speaks/wakes/consumes notices; reactions as the only
   passive-to-active channel.
Full design and rationale: ai-buddy-implementation-design.txt.

KNOWN DEFECTS AND LIMITS (APPLICATION)
--------------------------------------
- Stale breakpoint: a pause is driver memory; if the paused inference is
  superseded (e.g. /suspend, /abandon, /amend) /continue fails with "Only a
  prepared inference can be executed." and repeats; launcher restart recovers.
  Required: verify the paused inference state before resuming, drop a stale
  pause with a reason, add a regression test.
- Developer /interrupt discards partial output (only the "cancel" input
  policy keeps it).
- State duplication and save frequency contribute to G7.
- Retrieval is lexical; a prepared inference is offered before scheduling
  runs; host/driver.py name collides with "LLM driver" terminology.
