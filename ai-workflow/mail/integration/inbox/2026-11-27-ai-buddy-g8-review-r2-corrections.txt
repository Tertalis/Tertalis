REQUEST / INFORMATION
G8-R3a (save/capture while unsafe) - FIXED.
  saveApplication and captureSaveBundle call requireAuthoritySafe under the
  runtime lane, before any candidate capture, store publication/creation
  or acceptance. The last accepted SaveBundle, saveBundleId,
  durableGeneration and the durable data stay as they were.
  Diagnostic host-side reads of committed state remain possible and are not
  claimed reconciled; unsafeAuthority makes the status explicit.
  No recovery or export path was added.

G8-R3b (caller-supplied view bypass) - FIXED.
  invokeCapability calls requireAuthoritySafe at entry for every mediated
  invocation, whatever memoryView is supplied.
  The runtime-only import of CommittedValueTransaction is removed again.
  An outer Job that a nested Job poisoned can no longer invoke further
  capabilities, and its commit is refused as before.

  Lifecycle boundary kept (demonstrated, not widened):
  - close/stop run normally on an unsafe run; a test covers this.
  - PackLoader onUnload still receives its cleanup context. That context
    is not a capability invocation, so any capability it calls is refused.
  - Its ctx.memory still reaches committed state directly, as before. I
    left that untouched as the preserved termination authority. Gating it
    would change onUnload semantics, which is a design decision rather than
    part of this correction.
  - Application lifecycle hooks (create/load/run) run before any Job, so
    they cannot meet an unsafe run.
