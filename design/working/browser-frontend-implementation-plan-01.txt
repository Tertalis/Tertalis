1. STEP 2 - CODEENTRY FORMAT AND ROLE (backend, internal)
=========================================================

1.01. EDIT backend/packs/runtime.py
    a. CodeEntryDefinition: add format: str ("python-source@1" default) and
       role: str ("main" default).
    b. New module constants: PACK_KINDS = {"appPack", "modPack"};
       CODE_ENTRY_FORMATS = {"python-source@1", "js-module-source@1"};
       CODE_ENTRY_ROLES = {"main", "library"}; JS_SOURCE_LIMIT = 1 MiB.
    c. _definition(): reject kind outside PACK_KINDS (CP-2.07); reject
       unknown CodeEntry keys (today they are silently ignored, which is how
       a browser entry would be mis-executed); validate format and role;
       reject more than one main per format; reject python-source@1 with
       role "library" until the Python library loader exists (CP-2.08).
    d. New frozen dataclass DeclaredSourceEntry: packId, packVersion,
       codeEntryId, format, role, source (declared relative path),
       sourceBytes, sourceSha256, implementationId.
    e. Extract the existing path-containment / read / sha256 /
       implementationId code of _loadModule into _readSource(pack,
       definition, suffixes); _loadModule keeps executing python only.
       implementationId material uses the entry's own format instead of
       the literal "python-source@1" (byte-identical for python entries).
    f. _activatePack(): python-source@1 entries are executed exactly as now.
       js-module-source@1 entries are read via _readSource (suffix ".mjs",
       size <= JS_SOURCE_LIMIT) and recorded; no module execution, no
       context, no registration. Application-hook detection stays
       python-only.
    g. _LoadedPack gains declared: tuple[DeclaredSourceEntry, ...].
    h. New PackLoader.declaredEntries(format) -> tuple[DeclaredSourceEntry,
       ...] over active Packs in activation order; immutable snapshot.
    i. "pack-activation-completed" trace adds declaredEntryIds.

1.02. EDIT backend/context/codeEntryContext.py
    New read-only facade ctx.packs with declaredEntries(format), guarded by
    requireValid like every other facade. Constructor takes a
    declaredEntries callable (default: returns ()).

1.03. EDIT backend/application/applicationRuntime.py
    createContext() passes self.packLoader.declaredEntries to the context.

1.04. TESTS
    EDIT tests/backend/packs/test_packResolver.py: kind closed set; unknown
         CodeEntry key rejected; format/role validation; two mains per
         format rejected; python library rejected.
    EDIT tests/backend/packs/test_packLoader.py: js entry recorded, not
         executed (a deliberately invalid-Python .mjs proves it); bytes and
         sha256 recorded; root escape and wrong suffix rejected; size limit;
         python implementationId unchanged (regression); declaredEntries
         order and immutability; rollback leaves no declared entries.
    EDIT tests/backend/context/test_codeEntryContext.py: ctx.packs is
         invalid after context invalidation.
    NEW  tests/backend/packs/test_declaredEntries.py if the loader test file
         grows too large (decide at materialization).

3.03. NEW first-party/frontendHost/ (packId "frontend.host", kind "modPack")
    manifest.json   one python-source@1 main entry "host"
    __init__.py
    codeEntry.py    onLoad: validate config {"frontendHost": {"port",
                    "maxViews", "main": {"packId", "codeEntryId"}}}; create
                    FrontendHost; register frontend.host.channel@1 and
                    frontend.host.connection@1; onUnload closes
    host.py         FrontendHost: server lifecycle, per-run credential and
                    run id, View registry and cap (CP-8.04), endpoints
                    (CP-4.02), source table
    channel.py      FrontendChannel (thread-safe): declareTrack, set,
                    append, reset; waitInvocations(timeout); resolve(id,
                    result | flowError); bounded inbox, per-track ring
                    buffers, idempotency cache (CP-5.03)
    protocol.py     Representation: Invocation, Accepted, Result, FlowError,
                    event and gap shapes; limits; strict JSON validation
    bootstrap.html  Generic page: imports frontend.kit session.mjs, reads
                    the credential, fetches the authenticated descriptor,
                    imports the configured main entry, calls mount()
    README.md

    Source table: built when frontend.host.channel@1 is first called (after
    the whole activation plan), from ctx.packs.declaredEntries(
    "js-module-source@1"); served at /pack/<packId>/<codeEntryId> with the
    recorded bytes (exactly what was hashed), ETag = sha256. HTTP threads
    never touch the runtime or the filesystem.

3.04. Delivery seam (CP-3.03): the loop owner calls
    frontend.host.channel@1 once and then uses the channel directly from
    its own thread; stream observers inside Jobs may append from the lane
    thread. The channel never calls the runtime.

6. RISKS AND DECISIONS TO CONFIRM AT MATERIALIZATION
====================================================

6.01. Closing the kind set and rejecting unknown CodeEntry keys can break
out-of-tree manifests. All four known repositories comply today.
6.02. Returning a live channel object from a capability departs from
value-only results; it mirrors the observation bridge's grant objects and
is acceptable for trusted in-process Packs, but should be named in the
Flow integration review.
6.03. The viewer's relative import across tools/ and first-party/ is a
deliberate path trick (2.02). If it proves fragile, the fallback is a
fixed copy step - not preferred.
6.04. Rebasing bridge.py (3.02) touches security code; any behaviour
difference in test_bridge.py blocks the step.


7. MATERIALIZATION RECORD (STEPS 2-4, 2026-11-27)
================================================

7.01. Deviations from sections 1-3, all deliberate:
    a. Loader tests went to a new file
       tests/backend/packs/test_codeEntryFormats.py (covers 1.04 including
       the ctx.packs validity check); test_packResolver.py,
       test_packLoader.py and test_codeEntryContext.py are unchanged.
    b. Sources are served by declared source path
       (/pack/<packId>/<source>), not by entry id, so relative imports work;
       every imported module must be declared (kit manifest declares all
       eight modules; a kit test enforces it).
    c. Stream requests carry run=<runId>; positions from another run are
       ignored (needed for host restarts).
    d. Kit additions found necessary by the real-browser smoke:
       TrackStore.watch(); session.onState() reports the current state
       immediately; fetch is always called through an arrow wrapper
       (an unbound fetch throws "Illegal invocation" in browsers but not in
       Node - the same class of defect the G-02 smoke once caught).
    e. LoopbackHttpServer gained maxClients (connection/thread cap) for the
       threading variant used by the host.
    f. The host's bootstrap page lives in frontend.host (bootstrap.html,
       boot.mjs, boot.css); boot.mjs imports
       /pack/frontend.kit/bootstrap.mjs.
    g. Node is optional: tests/first_party/frontendKit/test_frontendKit.py
       skips without Node. The browser smoke
       (tests/first_party/frontendHost/smoke.py + browser-smoke.cjs) is a
       manual harness, as for G-02.

7.02. Verification in the assistant workspace (NOT the accepted Python 3.15
environment): Python 3.13 with a local shim for the 3.15 builtins
sentinel() and uuid.uuid7(). Full suite: same 34 environment-caused failures
before and after (all 3.13-related), +54 new passing tests. Node 22:
frontend kit suite 14/14, observation viewer suite 41/41. Real-browser smoke
(Chrome 153, playwright-core): passed - fragment removed, no storage or
cookies, two Views receive the same Emits, conflicting Continue gets
FlowError "conflict", a fourth View is refused by maxViews=3, host close
disconnects Views.

7.03. User verification, 2026-11-27, Windows, Python 3.15: full suite green,
after two Windows fixes:
    a. Test fixtures wrote browser sources in text mode (CRLF on Windows)
       while comparing exact bytes/hashes; they now write newline="\n".
    b. frontend.host rejected some POSTs before reading the body and closed
       the socket with unread data; Windows answers that with RST, which
       discards the response. Early POST rejections now half-close and
       drain the unread body (bounded: 1 MiB, 1 s) before closing.

7.04. Independent Windows integration check, 2026-11-27:
    Python 3.15.0b4, Node 23.11.0, Chromium 152.0.7977.65. The original
    working tree passed 1807 tests and the original browser smoke. Additional

    unresolved after credential rotation, pending-action retention exceeding
    its configured bound, and log snapshots larger than the kit body limit.
    These were corrected with regression coverage; cached Results were also
    frozen against later mutation by the loop owner. The expanded real-browser
    smoke passes with five Views, sixth-View rejection and an actual same-port
    host restart with an accepted action becoming unknown. Old tabs require
    a fresh launch link after credential rotation. Full suite: 1813 passed;
